# Stock ADR 0014: Apache License 2.0, copyright held personally

- **Status:** accepted
- **Date:** 2026-09-11

## Context

Stock is going public ahead of a presentation, and a pre-publication review
found it had no `LICENSE` file at all. With no license, default exclusive
copyright applies: a visitor can read the repository but has no legal right to
use, fork, or graft from it — which is the entire purpose of a "rootstock"
repo. This blocks going public regardless of what else is in order.

Two questions had to be answered, not one: which license, and whose name goes
on it.

**Which license.** Stock's graft model is clone-at-a-tag, drop history, point
at a new remote — a project built this way is meant to become fully the
grafter's own. A copyleft license (GPL, AGPL) would sit wrong against that:
it would read as obligating every grafted project to carry the same terms
forward, when the whole design is that grafting detaches a project from
Stock's history and lets it become whatever its owner wants. That leaves the
permissive family. Between MIT and Apache-2.0, the difference that matters
here is Apache-2.0's explicit patent grant and patent-retaliation clause —
the more "safe to build a company on" signal, relevant given this project is
explicitly meant to be taken seriously as real tooling rather than a
weekend script, and the audience for the presentation may include people
evaluating whether to build on it.

**Whose name.** "Graftwork" is a GitHub org and a repo name, nothing more —
not an incorporated legal entity. Copyright vests in a person or a legal
entity; it cannot vest in a name that is neither. The only accurate answer
today is the individual who wrote it.

## Decision

- **License:** unmodified Apache License, Version 2.0, as `LICENSE` at the
  repository root.
- **Copyright holder:** James Rennison, individually — recorded in `NOTICE`
  as `Copyright 2026 James Rennison`. This is not a permanent structural
  commitment: if Graftwork is ever incorporated, copyright can be reassigned
  to that entity with a simple, standard assignment. Nothing about licensing
  Stock today forecloses that later.
- **Vendored third-party content is unaffected.** The OpenSpec skill files
  under `.claude/skills/openspec-*/` are generated by `@fission-ai/openspec`
  and already declare their own MIT license in frontmatter — untouched per
  `WORKFLOW.md`'s existing rule, since they are regenerated and would lose an
  edit. `NOTICE` says so explicitly so a reader doesn't have to reconcile the
  two licenses themselves.
- **This is a docs-only change**, so per the route table in
  [`docs/RELEASING.md`](../RELEASING.md) it takes the direct route — branch,
  commit, PR — not a full OpenSpec change. It touches none of
  `openspec/specs/`, `scripts/`, or `tests/`.

## Consequences

- Stock's own files are clearly licensed, which is what unblocks sharing the
  repository publicly at all.
- **Grafting now silently carries a license decision that used to not exist.**
  `git clone --branch vX.Y.Z --depth 1` copies `LICENSE` and `NOTICE` like
  every other file, so a fresh graft inherits Apache-2.0 under this
  copyright holder unless the grafter deliberately changes it. The README's
  graft steps get an explicit line about this, the same treatment
  `stock-version` and the rewritten `README.md`/`CHANGELOG.md` already get —
  nothing here should happen invisibly to someone grafting without reading
  this ADR.
- `sorting-office` needs the same decision made independently. It is a
  separate repository with its own history and its own owner conversation;
  this ADR does not extend to it and should not be read as having settled
  it.

## Alternatives considered

- **MIT.** Simpler and at least as permissive, but drops the explicit patent
  grant for no offsetting benefit here. Rejected in favor of Apache-2.0.
- **A copyleft license.** Rejected outright — it contradicts the graft
  model's premise that a grafted project becomes fully its own, detached
  thing.
- **Attribute copyright to "Graftwork."** Rejected: not a legal person or
  entity, so copyright cannot actually vest there. Would have been a name on
  a document with no legal effect behind it.
- **Leave it unlicensed.** The status quo, and the reason this ADR exists —
  incompatible with a repository whose entire purpose is being copied from.
